# v0.1.0 — first release

First tagged release of the AI Code Review Assistant: a local-first, interactive pull-request
reviewer for GitHub PRs and GitLab MRs, backed by a model you choose and your own review standards.

Every change in this release is recorded in [`CHANGELOG.md`](../../CHANGELOG.md) (phases 1–49); this
file is the release-level summary.

## What it does

Point it at a PR/MR URL and it fetches the diff, selects the review rules that apply to the changed
files, asks a model for findings, anchors each finding to a real diff line, and opens a split-pane
workspace: code on the left, discussion on the right. You accept, edit, or push back on each
conclusion, then publish exactly one review with inline comments.

## Highlights

- **Your standards, not generic advice** — a local markdown skill library is injected per review,
  with rules chosen for the files that changed.
- **Anchored findings** — every finding maps to a valid diff line with its code context rebuilt from
  the real PR diff.
- **A review you can argue with** — reference other threads with `#N`, stream replies token by token,
  retry or cancel one thread, and push back on the AI verdict so it re-reads the review against your
  reasoning and says whether it changed its mind.
- **Publish only what you approve** — accepted findings become one review with inline comments;
  `REQUEST_CHANGES`, `APPROVE` (no findings needed) or `COMMENT`.
- **Existing conversations included** — import current PR comments, sync new replies, and manage AI
  findings and human discussions in one workspace.
- **Watching** — follow a PR and review only the delta when its head commit changes.
- **Self-improving standards** — *Evolve from review history* reads the last 30 days of reviews and
  the corrections in their comment threads, proposes diffs against the guideline files, and either
  applies them or clones the foundation.
- **Push-back lessons (beta)** — turn a rejected finding into a reusable rule file for a foundation.
- **Deterministic pre-pass** — optional regex packs (committed token prefixes, private-key headers,
  conflict markers, debugger statements, `console.log`, focused tests) at zero tokens.
- **Standing policies** — review PRs in a repository that are waiting on you, capped per tick.
- **Cross-review finding search** — normalised finding keys, prior-match hints, recurring patterns.
- **Side-by-side model comparison** — re-run one diff with a second model, priced before it starts.
- **Usage analytics** — a ledger of calls, tokens, latency, estimated cost, acceptance and push-back
  rate per review, per model.

## Models and credentials

Ollama Cloud (default), Claude, OpenAI/Codex, OpenCode Zen and OpenCode Go, plus a local Ollama
daemon. Provider keys, VCS tokens and account credentials are encrypted at rest when
`CREDENTIALS_ENCRYPTION_KEY` is set; nothing leaves the machine except the diff and prompts sent to
the chosen provider.

## Install

Requirements: Python 3.12, Node.js 18+, PostgreSQL 14+ (SQLite works for a trial), a GitHub token or
GitLab personal access token, and a model provider key or a local Ollama daemon.

```bash
# backend
cd backend
uv venv --python 3.12 .venv && source .venv/bin/activate
uv pip install -r requirements.txt
createdb code_review
cp .env.example .env
uvicorn app.main:app --reload --reload-exclude 'tests/*.py' --reload-exclude 'alembic/*.py' \
  --reload-exclude '*.db' --port 8000

# frontend (second terminal)
cd frontend
npm install
npm run dev          # http://localhost:5173, proxies /api to :8000
```

Startup applies the Alembic migrations. Health: `http://127.0.0.1:8000/api/health`; OpenAPI docs at
`/docs`. Account setup, then **New code review**.

## Deployment artifacts

- **Container** — `docker build -t code-review-master:0.1.0 .` then
  `docker run --rm -p 8000:8000 -v code-review-data:/data code-review-master:0.1.0`. One image serves
  the API and the compiled SPA on port 8000; `/data` holds the SQLite database, skill foundations and
  the editable default skill library.
- **Vercel + Supabase** — `vercel.json` deploys `web` and `api` as two Services on one domain;
  `SERVERLESS=true` switches to `NullPool`, skips startup migrations, disables skill writes and hides
  the local Ollama daemon. Run `alembic upgrade head` once from outside the platform.
- **Source package** — `code-review-master-0.1.0.zip` / `.tar.gz`, produced with `git archive` from
  the release tag (tracked files only; no secrets, databases, `node_modules` or build output).

## Known limitations

- One uvicorn worker: the discussion stream and job bus are in-process.
- Serverless: ingest runs as a background task and progress is persisted in `review_events`; a
  deployment with no watch tick runs no standing policies.
- GitLab supports one discussion per finding (no "review with N comments"); approval is best-effort.
- Summarisation on publish is best-effort — on failure the last message per thread is posted with a
  warning.
- Large diffs are reviewed in parts rather than truncated.
