# Essential checks

- **Data.** Run migrations and inspect the generated SQL and schema. Evaluate locks, scans, rewrites, rollback, existing-data violations, and downstream callbacks. Use database constraints for concurrent invariants, route reads by consistency semantics, and keep related reads on one role.
- **Async work.** Do not publish work that depends on uncommitted state. Choose after-commit or outbox/inbox from business criticality. Make consumers idempotent where delivery can repeat. Retry only recoverable failures with bounded attempts, jitter, deduplication, and a terminal path.
- **Authorization.** Scope every object and supplied identifier to its tenant, parent, or authorized identity. Test negative cross-tenant cases. Preserve authoritative scope, invalidation, revocation, and failure behavior when caching permissions or flags.
- **Boundaries.** Inventory producers, consumers, schemas, defaults, and transitive callers before changing a shared contract. Preserve compatibility or provide sequencing, telemetry, rollback, and removal criteria.
- **Contract shape.** When a shared builder, serializer, or response hash gains or loses a key, sweep the spec tree for every exact-shape assertion — `contain_exactly(*keys)`, `match_array(keys)`, and a literal `keys.size == N` — and update each key list and count. A change that updates one spec file leaves the others red for an unrelated reason; name every affected file.
- **Reachability.** A new field can be assigned correctly and still be unreachable for the cohorts the contract names. For each cohort, trace the candidate query or filter that produces rows and confirm a row in the target state survives it. A scope that filters on the same attribute, or drops the categories that carry the state, makes the value untestable there: scope the criterion to the cohorts whose list carries that state, or record the deviation in the contract and the doc.
- **Performance.** Bound request, job, query, export, and dependency work. Batch and stream large datasets. Require workload, baseline, and before/after evidence for optimization, scaling, timeout, concurrency, and resource-limit claims.
- **Operations.** Define ownership, observability, alerting, recovery, cleanup, and post-deployment verification. Diagnose duplicate work, OOMs, and noisy telemetry at their source before increasing capacity or silencing a sink.
- **Tests.** Exercise the failure mode that matters: duplicate delivery, retry exhaustion, partial completion, cross-tenant access, concurrency, rollback, or global-state leakage. A test must prove the intended destination or state transition, not merely that code ran.
- **Test efficacy.** Check where every asserted value comes from. An expectation that equals a constant the test double returns cannot fail when production stops computing it, and a type assertion such as `be_a(Numeric)` accepts `0.0` as readily as an unpopulated field. Assert the figure the fixture makes computable, and delete an example whose only input is the stub. Four shapes recur beside those:
  - An assertion on the size of a list the spec itself wrote (`expect(KEYS.size).to eq(18)` under an 18-entry literal) restates the fixture; the sibling `match_array(KEYS)` is the assertion that bites, and the size line only reads as the criterion's proof.
  - A collaborator chosen by a predicate needs one example per branch, and the branch a real member takes is the one to exercise. An example that forces the selector false tests only the fallback, so the path the new cohort actually runs stays untested while the example still names the cohort.
  - An identity over the response's own fields (`projected == current + accrual`) holds when both terms are wrong by the same amount; state the concrete figure the fixture makes computable beside it.
  - A result reader that only `call` populates returns nil when the caller forgets to invoke it. Wrapper services commonly assign their arguments in `initialize` and compute in `call` or `perform`, so `Service.new(...).data` is nil forever and nothing raises. Read which method assigns the attribute before accepting a change that reads it, and compare the sibling class the change copied its shape from — a class that follows a sibling's constructor usually follows its invocation too, and the gap between the two is the defect. Require the spec to stub the inner collaborator rather than the result reader: an example that stubs `#data` stays green whether or not `call` ran, and a `null` value is ordinarily legal under the response contract.
- **Proposals.** State the problem, non-goals, current behavior, constraints, success criteria, and business criticality. Compare the smallest viable options and separate required contract parity from optional enhancements.
